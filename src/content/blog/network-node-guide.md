## 节点、订阅、客户端分别是什么

刚接触时，这几个词很容易混在一起，可以这样理解：

- **节点**：客户端连接的远端代理端点，通常包含服务器地址、端口、协议和认证信息。
- **订阅**：获取或更新配置的一种方式。订阅里可能包含多个节点，也可能附带策略组、分流规则等配置，实际内容取决于服务和格式。
- **客户端**：安装在电脑上、读取配置并建立连接的软件。不同客户端支持的协议和订阅格式可能不同。
- **规则**：决定一条连接应该直连，还是交给某个代理节点或策略组处理。

对于通过代理转发的连接，可以把路径想成：

```text
应用 → 本机客户端 → 远端节点 → 目标网站
```

直连流量则不经过远端节点。所以，“导入了订阅”“选中了节点”和“应用真的使用了代理”是三个需要分别确认的环节。

## 电脑端从哪里开始

不同软件的按钮名称会有差异，下面是一套通用顺序，具体操作以所选客户端和服务的说明为准。

1. **选择合适的客户端。** 打开上面的下载入口，核对操作系统、处理器架构和软件来源，不确定时先看对应项目的安装说明。
2. **获取匹配的配置。** 在服务网站查看使用教程，选择客户端支持的订阅格式。不要把网站首页地址当成订阅链接。
3. **导入并更新。** 在客户端的订阅或配置管理中导入，确认更新成功、节点列表正常显示，再启用这份配置。
4. **选择节点。** 先选一个可连接的节点，进行一次延迟测试，再实际打开自己需要的网站。
5. **确认流量入口。** 如果客户端提供系统代理开关，可按说明开启；部分软件不读取系统代理，需要单独配置。
6. **用实际任务验证。** 看文档是否顺畅、下载是否持续、连接是否频繁中断，比只看延迟数字更有意义。

以 mihomo 为例，规则、全局和直连是不同运行模式；其配置文档还单独定义了代理集合的更新和健康检查。使用这类客户端时，要区分配置更新、节点检测和流量路由这几个环节。参见 [mihomo 全局配置](https://wiki.metacubex.one/config/general/) 与 [代理集合配置](https://wiki.metacubex.one/config/proxy-providers/)。

## 节点怎么选：先看实际可用性

节点名称中的地区通常表示服务标注的位置，不能单凭名字判断实际线路质量。地理距离也不能直接代替真实测试。

可以按下面的顺序比较：

- **连通性**：目标网站是否真的能打开，而不只是检测按钮显示成功。
- **稳定性**：连续使用一段时间，看看是否断流或频繁重连。
- **延迟**：同一客户端、同一测试地址下的结果更适合横向比较。
- **吞吐量**：下载速度需要单独观察，低延迟不等于高带宽。

建议保留一个常用节点和一个备用节点。出现异常时，只切换节点、保持其他条件相同，更容易判断问题出在哪里。测速也会消耗流量，不必反复跑大文件测试。

## 常见问题，按这个顺序查

### 导入成功，却没有节点

先检查配置是否更新成功，再核对订阅格式和客户端支持情况。服务账号是否有效、订阅是否被重置，也需要在服务后台确认。具体原因优先看更新日志中的错误提示。

不要把带有个人令牌的订阅链接发到公开评论区或在线转换网站。求助时，隐藏链接、二维码和认证字段即可。

### 节点有延迟，但网页打不开

延迟测试通常只验证某个测试目标，不能证明所有网站都可用。先确认当前配置、策略组选中的节点，以及目标连接命中了哪条规则；再查看是否存在域名解析错误或连接超时。

一次只改一个设置。先换备用节点，再比较同一个网站的结果，避免同时改 DNS、规则和代理模式后无法判断哪一步起了作用。

### 浏览器能用，其他软件连不上

检查该软件是否读取系统代理、是否有自己的代理设置，以及客户端日志里有没有对应连接。开发工具和终端可能需要单独设置代理地址与端口，数值应从自己的客户端读取。

如果所用客户端支持 TUN 等流量接管方式，先阅读其平台说明和权限要求，再决定是否启用。

### 白天正常，晚上变慢

可以在同一网络下比较备用节点，再换手机热点复测。这样能帮助区分本地网络和远端线路问题。高峰期拥堵、无线信号、后台下载等都可能影响体验，具体原因需要通过对照测试判断。

### 退出客户端后，普通网页也打不开

先查看系统代理设置。如果它仍指向已经停止运行的本机代理端口，应用可能无法建立连接。可以重新打开客户端关闭系统代理，或在系统设置中移除确认无用的代理配置，然后复测。

## 留一份方便排查的记录

遇到问题时，比起只写“不能用”，记录下面几项更容易定位：

```text

系统与客户端版本：
当前网络：家庭宽带 / 手机热点 / 其他
故障现象：全部无法连接 / 只有某个网站异常 / 速度慢
订阅更新结果：
切换备用节点后的结果：
已脱敏的错误日志：
```
